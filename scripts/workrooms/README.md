# Managed Workrooms addresses · Mac rehearsal

From Connect to your VPS choose **Set up a VPS without a domain**. Enter the public IPv4 of a fresh Ubuntu VPS and a workspace slug. Select the private key from the Mac's SSH folder that you already used to log in. Terminal handles the passphrase and the BraveBrand Team access link from Skool. The installer runs over SSH, registers a DNS-only address, starts the invite-only community and pairing endpoint with Caddy, and waits for public HTTPS discovery before returning to Buzz onboarding. Existing addresses and employee invites take the usual path.

This branch implements address registration and server setup. First-owner enrollment and employee invitations are subsequent rehearsal checkpoints. The initial server administrator key is retained root-only in /opt/bravebrand/workrooms/owner.key. The Mac's private SSH key stays on the Mac. Relaunch with the same IP and slug after a failure. Keep VPS state and the D1 reservations backed up. Remove the DNS record before releasing a server IP. Reassigning an active name or changing IPs requires an operator ownership check.

## One-time operator setup

1. Use the authoritative Cloudflare zone for workrooms.bravebrand.com (a delegated zone can confine the DNS token to that zone). Ensure this subdomain is reserved for client servers. Avoid parent-domain session cookies on the client hostname namespace.
2. Create the workrooms-addresses D1 database. Copy registrar/wrangler.example.jsonc to a local Wrangler config and fill in its database and zone IDs. Apply registrar/schema.sql with Wrangler D1 execute against that database. Configure DNS_TOKEN via Wrangler secret put with DNS write permission on that zone. The registration service is deployed at workrooms-setup.bravebrand.com. Require direct IPv4 requests, disable Pseudo IPv4 overwrite, and apply rate limiting to POST /v1/address. Keep request bodies and membership links out of logs.
3. Deploy the Worker with the reviewed config and verify the custom domain and TLS. The installer checks the same Standard and Premium membership endpoint used by the Team plugin. The Worker uses the caller IPv4, a persistent VPS claim secret and two database uniqueness constraints. Concurrent or repeated requests can only complete the original binding. Existing records are never replaced.
4. Build the Apple silicon rehearsal app with VITE_BRAVEBRAND_MANAGED_ADDRESS=true scripts/bravebrand-client.sh --rehearsal. Without the build flag, the current onboarding is preserved. Use the rehearsal identity and data directory. Check the new artifact before updating the download.

The setup templates adapt the tested BraveBrand VPS pilot at Auto Agency 50b41fce, tools/buzz-vps-pilot, based on block/buzz. Community traffic, pairing, TLS private keys and database storage stay on the client VPS. The VPS does not receive a DNS API token. TCP 80 and 443 must be publicly reachable and the SSH host must already be trusted on the Mac.
